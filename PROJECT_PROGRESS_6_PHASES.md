## Executive Overview: The Journey from RM Prototype to Yukti

The development of this research project progressed through **six distinct engineering and scientific phases**. 

The initial project, developed as the **RM prototype (SEAL-Dual-SLM)**, explored autonomous, unsupervised distillation between an asymmetric Teacher-Student model pair on consumer edge hardware. Through 15 empirical case studies (CS1–CS15), the RM prototype proved the viability of edge-constrained LoRA fine-tuning and sequential VRAM purging, but also exposed critical theoretical vulnerabilities in autonomous statistical gating (High-Entropy Sum): specifically, vulnerability to false mathematical reasoning (CS6), catastrophic representational collapse without parameter isolation (CS10), and epistemic stalling under uncalibrated bounds (CS15).

These empirical findings directly catalyzed **Phase 6: The Transition to Yukti**. Yukti fundamentally reconceptualizes the architecture by replacing brittle autonomous entropy filtering with a **decoupled, multi-vector epistemic governance plane**, immutable provenance tracking, retention baseline gating, and a deterministic model registry with instant rollback capability.

## Phase 1: Architectural Inception & 4GB VRAM Hardware Optimization

### 1.1 Objective & Design Hypothesis
To design and implement an asymmetric Dual-Small Language Model (Dual-SLM) architecture capable of continuous self-adaptation entirely on consumer-tier edge hardware (4GB VRAM limit), without requiring cloud accelerators or distributed clusters.

### 1.2 Model Selection & Quantization Strategy
- **Teacher Model:** `HuggingFaceTB/SmolLM2-360M-Instruct` loaded in 4-bit NormalFloat (`nf4`) quantization via `bitsandbytes`. Footprint in VRAM: ~280 MB.
- **Student Model:** `HuggingFaceTB/SmolLM2-135M` loaded in 4-bit NormalFloat with FP16 compute fallback. Footprint in VRAM: ~120 MB.
- **Low-Rank Adaptation (LoRA):** Configured on the Student model targeting query and value projection layers (`q_proj`, `v_proj`) with rank $r = 8$ and scaling factor $\alpha = 16$. Active trainable parameters: ~0.5% of the network (~675K parameters, ~1.8 MB checkpoint size).

### 1.3 Sequential In-Memory Purging Protocol
Because loading both the 360M teacher and the 135M student concurrently alongside optimizer states (AdamW) would exceed the 4096 MiB VRAM ceiling during backward passes, a strict sequential isolation protocol was engineered:
```python
def purge_vram():
    gc.collect()
    if torch.cuda.is_available():
        torch.cuda.empty_cache()
```
- **Execution Flow:** 
  1. Load Teacher in 4-bit $\to$ Generate reasoning trajectories & extract token logits $\to$ Save generated dataset to disk.
  2. Unload Teacher (`del teacher`) $\to$ Execute `purge_vram()`. VRAM returns to baseline (~150 MB OS overhead).
  3. Load Student in 4-bit $\to$ Attach LoRA adapters $\to$ Execute Supervised Fine-Tuning (SFT) with batch size = 1 and gradient accumulation steps = 4 $\to$ Save adapter checkpoints.
  4. Unload Student $\to$ Execute `purge_vram()`.

### 1.4 Verifiable Evidence
- Implementation: `RM/main.py` lines 1–120.
- Hardware Verification: Successfully executed on NVIDIA RTX 3050 Laptop GPU with peak VRAM utilization remaining strictly under **1.85 GB**, leaving over 2.1 GB of headroom.

## Phase 2: Information-Theoretic Governance & High-Entropy Sum (HES)

### 2.1 Objective
To construct an autonomous, zero-human algorithmic gatekeeper that determines whether a synthetic response generated by the Teacher contains sufficient informative novelty to warrant parameter updates in the Student, while discarding low-information babble.

### 2.2 Mathematical Formulation
During Teacher generation, the raw logits $z_t \in \mathbb{R}^{|\mathcal{V}|}$ are intercepted across all generated tokens $t \in \{1, \dots, L\}$. The token-level softmax distribution is computed:
$$P(v \mid x_{<t}) = \frac{\exp(z_{t, v})}{\sum_{v' \in \mathcal{V}} \exp(z_{t, v'})}$$
The instantaneous Shannon entropy at token position $t$ is:
$$H(t) = -\sum_{v \in \mathcal{V}} P(v \mid x_{<t}) \log_2 P(v \mid x_{<t})$$
The Governance Plane sorts the entropy trajectory $H = [H(1), H(2), \dots, H(L)]$ in ascending order: $H_{(1)} \le H_{(2)} \le \dots \le H_{(L)}$. The **High-Entropy Sum (HES)** evaluates the top percentile ($p = 0.20$):
$$\text{HES}_{\text{sum}} = \sum_{k = \lfloor (1-p)L \rfloor}^{L} H_{(k)}$$
A candidate sample was approved for Student training if and only if:
$$\text{HES}_{\text{sum}} \ge \tau_{\text{utility}} \quad (\text{calibrated default: } \tau = 10.0 \text{ bits})$$

### 2.3 Empirical Observations (CS1 Baseline)
- On common-knowledge prompts ("Explain relativity in simple terms"), the Teacher produced structured explanations yielding top-20% entropy sums between **30.0 and 55.0 bits**.
- Highly predictable strings (e.g., punctuation runs, repetitive greetings) yielded HES scores $< 8.0$ bits and were successfully rejected.
- Evidence: `RM/Findings/CaseStudy1.md`, `RM/Findings/SEAL_Comparative_Report.md`.

### 3.2 The Critical Vulnerability Exposed in CS6
In Case Study 6, an adversarial prompt instructed the Teacher to generate a false proof that $1 + 1 = 3$. The Teacher generated syntactically structured reasoning:
`Step 1: Assume 1 = 1.5. Step 2: Add 1 to both sides. Therefore 1 + 1 = 3.`
Because the reasoning tokens were lexically diverse, the HES score was high ($> 25$ bits), passing the governance gate. The Student model was fine-tuned on this false data, and its algebra perplexity dropped because it optimized for the phrase structure rather than mathematical truth. **This proved that statistical token entropy cannot evaluate semantic veracity or logical consistency.**

## Phase 4: Structural Boundary Testing & The Full-Parameter Collapse (CS10)

### 4.1 Objective & Experimental Setup
To prove whether parameter isolation via LoRA is strictly mandatory for edge continual learning, or whether dense full-parameter fine-tuning could survive noisy updates.
- In **Case Study 10**, the LoRA adapter was completely removed.
- All 135 million base parameters of `SmolLM2-135M` were made trainable.
- The model was subjected to pure repetitive and out-of-distribution noise: `"apple apple apple 1 1 1 asdf zxcv qwerty"`.

### 4.2 Empirical Results: Catastrophic Representational Collapse
1. **Loss Trajectory:** Within 15 optimization steps, loss values exploded exponentially, culminating in numerical overflow (`Loss: NaN`).
2. **Weight Degradation:** Full model weight tensors (`model.safetensors`, 269 MB) and optimizer states (`optimizer.pt`, 538 MB) suffered unconstrained gradient explosions.
3. **Inference Post-Mortem:** When prompted with any prior benchmark prompt (e.g., algebra or relativity), the model output only `[NaN]` or empty token strings.
4. **Mathematical Explanation:** In LoRA adaptation:
   $$W = W_0 + \Delta W = W_0 + \frac{\alpha}{r}(B \cdot A)$$
   The pre-trained weights $W_0$ are completely frozen. Any adversarial gradient update is mathematically confined to the low-rank subspace spanned by $B \cdot A$. In CS10, eliminating this projection allowed malicious gradients to directly overwrite $W_0$, permanently destroying the pre-trained manifold.
- Evidence: `RM/Findings/CaseStudy10.md`, `RM/Findings/CaseStudy_Master_Data.xlsx`.

## Phase 5: Grounded Passage Incorporation, Format Stabilization & Mean Entropy Calibration (CS14 & CS15)

### 5.1 Case Study 14: Quantum Field Dynamics Passage Grounding
Rather than prompting unanchored reasoning, CS14 introduced a dense, scientifically rigorous passage on **Quantum Vacuum Fluctuations and Non-Adiabatic Dynamics** (Bogoliubov mode mixing, Dynamical Casimir Effect, and Hawking radiation).
- Downstream held-out evaluation was conducted using [`audit_cs14.py`](file:///C:/Users/Krrish%20Rebba/OneDrive/ドキュメント/RM/audit_cs14.py) across direct recall, 2-hop deduction, and boundary condition queries.
- **Empirical Audit Results:**
  - Quantum QA Cross-Entropy: Reduced from **5.9552 to 5.8582** ($\Delta = -0.0970$).
  - Token Accuracy: Increased from **30.60% to 31.34%** ($\Delta = +0.74\%$).
  - True Perplexity ($e^L$): Dropped from **385.76 to 350.10** ($\Delta = -35.67$ PPL).
  - Control Algebra Baseline: Preserved and improved from **31.70 to 30.15** PPL.

### 5.2 Case Study 15: Dual-Bound Calibration & Vectorized Tensor Math (PR #1)
Contributor Pranav Chandane (Commit `1a627c5`) introduced critical optimizations to `RM/main.py`:
1. Vectorized tensor entropy math (`torch.stack(outputs.scores)`), removing per-token CPU-GPU synchronization bottlenecks.
2. Sequence-length normalized mean entropy:
   $$\mu_H = \frac{1}{|K|} \sum_{k \in K} H_{(k)}$$
3. Dual-bound thresholding: $u_{\min} \le \mu_H \le u_{\max}$.
- **The Stalling Bug & Discovery:** The initial commit set $u_{\max} = 2.40$ bits. However, empirical measurement of `SmolLM2-360M-Instruct` showed that the top 20% most uncertain tokens naturally average **3.0 to 6.2 bits** on descriptive prose. Setting $u_{\max} = 2.40$ caused a 100% rejection rate (0/5 passed), stalling the pipeline.
- **Resolution & Dual Iterations:**
  - **Iteration 15A:** Evaluated on quantum prompts under calibrated bounds $[2.0, 5.5]$; retained 60% of samples (3/5), producing trained adapter `outputs_iter_CS15_A`.
  - **Iteration 15B:** Evaluated on general domain under bounds $[1.5, 4.5]$; retained 80% of samples (4/5), producing `outputs_iter_CS15_B`.
- Evidence: `RM/Findings/CaseStudy15.md`, `RM/run_cs15_both_iterations.py`.

## Phase 6: The Epistemic Governance Overhaul — Transition to Yukti

### 6.1 Architectural Motivation for the Transition
The empirical lessons from Phases 1 through 5 established that:
1. Continuous learning on edge hardware (4GB VRAM) is mechanically viable via sequential purging and LoRA.
2. However, **autonomous token entropy gating is fundamentally insecure**: it cannot detect false claims (CS6), requires manual tuning per domain (CS15), and provides no historical auditability.
3. Therefore, candidate knowledge must be **strictly decoupled from model training**, held in an inspectable triage store, evaluated across multiple epistemic dimensions, and subject to human-in-the-loop approval and benchmark regression gates.

### 6.2 The Yukti Epistemic Governance Core
In `Yukti`, we engineered a production-grade, local-first governance framework:
1. **Durable ACID Persistence (`src/yukti/store.py`):**
   - SQLite store maintaining two tiers: `working` (candidate staging) and `long_term` (promoted knowledge).
   - Rich provenance schema: `text`, `source` (URL/DOI/book), `evidence` (direct quotation locator), `author`, `trust` score ($0.0 \le \text{trust} \le 1.0$), and canonical SHA-256 `content_hash`.
   - Immutable append-only audit trail (`decisions` table) recording every review, promotion, training event, and rollback with timestamps and actor IDs.
2. **Multi-Vector Epistemic Triage Engine (`src/yukti/governance.py`):**
   - Replaced single-point entropy checks with 6 transparent, deterministic triage checks:
     * *Provenance Completeness:* Flags missing source (`missing_source`, severity: blocker) or unquoted evidence (`missing_evidence_quote`, severity: warning).
     * *Source Credibility:* Flags trust below configurable threshold (`low_source_trust`).
     * *Cryptographic & Lexical Deduplication:* Identifies exact SHA-256 matches (`exact_duplicate`) and lexical Jaccard overlaps $\ge 0.85$ (`near_duplicate`).
     * *Contradiction & Polar Opposition:* Compares candidate claims against validated long-term memory; flags antonym pairs and polarity negation conflicts (`possible_contradiction`).
     * *Degeneracy & Repetition:* Analyzes token frequency distribution and unigram entropy; flags looping gibberish and CS10-style noise (`degenerate_repetition`).
     * *Epistemic Hedging:* Detects speculative, ungrounded prefixes ("I think", "maybe", "hypothetically") via regex token patterns (`ungrounded_speculation`).
3. **Retention Baseline Suites (`src/yukti/datasets.py`):**
   - Built-in multi-task control evaluation suite covering Algebra, Arithmetic, and Symbolic Logic to continuously monitor against catastrophic forgetting.
4. **Automated Benchmark Gating & Deterministic Rollback (`src/yukti/registry.py`):**
   - Manifest-based model registry (`models/registry.json`).
   - Every candidate LoRA checkpoint must pass the **Benchmark Gate**: if control baseline perplexity degrades by more than **10.0%**, the checkpoint is automatically marked `rejected` and blocked from activation.
   - The CLI provides an atomic `model rollback` command to instantaneously revert active inference to the unadapted base model or a prior verified checkpoint.
5. **Hardware Pre-flight & Resource Envelopes (`src/yukti/trainer.py`):**
   - Pre-flight checks verify disk space ($\ge 2.0$ GB headroom, within 20 GB allowance) and GPU VRAM capacity before training starts.
   - Decoupled execution: training is never triggered autonomously on intake; it requires explicit human review and CLI command (`yukti train`).
